# Liverpool Gaming — ربط الواجهة بالخادم

## ما تم ربطه
- نموذج حساب المالك وتسجيل الدخول يستخدم Supabase Auth REST API (بريد إلكتروني وكلمة مرور) ثم يطلب التحقق من العضوية والدور عبر الخادم.
- تهيئة المالك الأول محمية برمز `OWNER_BOOTSTRAP_CODE` محفوظ في بيئة الخادم فقط؛ لا تضعه في متغير `VITE_`.
- بيع البوفيه يرسل السلة كلها إلى `POST /api/finance/sales` وينتظر رد الخادم قبل طباعة الإيصال أو مسح السلة. الخادم يعيد حساب السعر ويخصم المخزون ويسجل الفاتورة وحركة الخزنة في transaction واحدة.
- أضف الصنف/أعد التوريد عبر API؛ زيادة أو نقص المخزون تسجل حركة منفصلة مع منع الرصيد السالب.
- المصروفات والسلف وحركات الخزنة تنتظر تأكيد الخادم قبل عرض النجاح.
- إضافة قراءة للمخزون وسجل الخزنة. تكلفة الصنف لا تُرسل إلى دور الكاشير.
- حفظ مفتاح idempotency لمحاولة البيع نفسها حتى يمكن إعادة المحاولة دون تكرار العملية إذا ضاع رد الشبكة.

## نقاط يجب الانتباه لها
- تم تنفيذ تغييرات الكود لكن لم يمكن تشغيل `npm run lint`, `npm test`, أو `npm run build` داخل بيئة العمل الحالية؛ الاعتماديات في `node_modules` كانت ناقصة/غير مكتملة، ومحاولة التثبيت انتهت بمهلة اتصال. لذلك لا أصف المشروع بأنه مختبَر بالكامل أو جاهز للإنتاج.
- يجب مراجعة البيانات المحلية القديمة؛ مخزون الخادم يبدأ من الجداول الجديدة، ولا تُعتبر أصناف `localStorage` مخزونًا معتمدًا.
- يجب فتح وردية قبل عمليات البيع والخزنة.
- الفوترة الأساسية لجلسات اللعب وإغلاق الوردية ليست كلها معاملات مالية ذرية على الخادم حتى الآن؛ التغيير يركز على بيع البوفيه والمخزون وحركات الخزنة.
- أضف مستخدمي الموظفين يدويًا إلى `public.liverpool_app_members` بعد إنشاء حساباتهم في Supabase Auth، باستخدام UUID الصحيح ودور `cashier` أو `supervisor` أو `admin`. لا تمنح `owner` إلا للمالك الفعلي.

## قبول ما قبل الإنتاج
1. `node --check server/index.cjs`
2. `npm install` ثم `npm run lint`, `npm test`, `npm run build`
3. تأكد من `/api/health` يعيد `database: connected`.
4. جرّب مستخدمًا بلا عضوية، وكاشيرًا، ومشرفًا، ومالكًا؛ تأكد أن صلاحيات الخادم تمنع العمليات غير المسموحة.
5. اختبر بيع صنف بمخزون 1 بكمية 2: يجب رفضه دون فاتورة أو حركة خزنة أو تغيير مخزون.
6. اختبر بيعًا متعدد الأصناف: يجب أن تُحفظ الفاتورة والبنود والخصم وحركة الخزنة معًا أو لا يُحفظ أي منها.
7. أعد إرسال الطلب بنفس `idempotencyKey`: يجب ألا يتكرر البيع.
8. اختبر انقطاع الشبكة، وإعادة تشغيل الخادم، وتسجيل الخروج، وانتهاء جلسة Supabase.
9. قارن دفتر الخزنة والمخزون بتقرير Supabase بعد كل اختبار.
