# تشغيل Liverpool Gaming — Windows PowerShell

## 1) تثبيت الاعتماديات
افتح PowerShell داخل مجلد المشروع الذي يحتوي `package.json` ثم نفّذ:

```powershell
npm install
```

إذا كان المشروع يستخدم ملف القفل وتريد تثبيتًا مطابقًا، استخدم بدلًا منه `npm ci`.

## 2) إعداد البيئة
انسخ ملف المثال:

```powershell
Copy-Item .env.example .env
notepad .env
```

اترك `SUPABASE_URL` و`SUPABASE_PUBLISHABLE_KEY` و`VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` كما هي إذا كانت تخص مشروع Liverpool Gaming الصحيح. غيّر `OWNER_BOOTSTRAP_CODE` إلى سر عشوائي طويل (32 حرفًا على الأقل)، واحتفظ به لنفسك؛ ستدخله مرة واحدة في شاشة إنشاء حساب المالك. يجب إدخال `DATABASE_URL` من Supabase Dashboard > Project Settings > Database > Connection string. استخدم بيانات اتصال الخادم فقط، ولا تضع كلمة مرور قاعدة البيانات في أي متغير يبدأ بـ `VITE_` ولا ترفع ملف `.env` إلى Git.

إذا كان الاتصال المباشر غير متاح في بيئة الاستضافة، استخدم connection string المناسب من Supabase (Pooler) مع المنفذ/وضع الاتصال المعروض في لوحة التحكم. لا تخمّن كلمة المرور أو عنوان المضيف.

## 3) فحص الملفات
```powershell
node --check server/index.cjs
npm run lint
npm test
npm run build
```

لا تنتقل للتشغيل الفعلي إذا فشل أي فحص؛ أصلح الخطأ أولًا.

## 4) تشغيل التطوير محليًا
افتح نافذتي PowerShell في مجلد المشروع.

النافذة الأولى (API والخادم):
```powershell
npm run server
```

النافذة الثانية (واجهة Vite):
```powershell
npm run dev
```

افتح العنوان الذي يطبعه Vite في المتصفح. يجب أن يعمل API على `http://localhost:3001` والواجهة على منفذ Vite `3000`، والـ proxy يمرر `/api` إلى الخادم.

## 5) تشغيل نسخة الإنتاج محليًا
```powershell
npm run build
npm run start
```
ثم افتح `http://localhost:3001`.

## 6) تحقق من صحة الخادم
في نافذة PowerShell أخرى:
```powershell
Invoke-RestMethod http://localhost:3001/api/health
```
المتوقع `{ ok: true, database: "connected" }`. هذا يفحص اتصال قاعدة البيانات فقط، ولا يثبت وحده سلامة كل العمليات المالية.

## تنبيهات تشغيل
- تسجيل الدخول أصبح بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth، وليس PIN المحلي.
- إذا كانت ميزة تأكيد البريد الإلكتروني مفعلة في Supabase، أكّد البريد قبل تسجيل الدخول. تهيئة المالك الأول تتطلب `OWNER_BOOTSTRAP_CODE` الموجود في الخادم؛ لا تشاركه مع الموظفين ولا تضعه في متغير يبدأ بـ `VITE_`. بعد تهيئة المالك، أضف حسابات الموظفين إلى `public.liverpool_app_members` بالأدوار المسموحة عبر عملية إدارية آمنة.
- يجب فتح وردية قبل بيع البوفيه أو تسجيل حركة خزنة.
- جداول البيع والمخزون والخزنة الجديدة تبدأ فارغة. سجّل/استورد الأصناف إلى المخزون من داخل التطبيق بعد الدخول.
- عمليات جلسات اللعب وإغلاق الوردية القديمة ما زالت تعتمد على نموذج الحالة المحلي/المتزامن، ولم تُحوّل كلها إلى دفتر مالي ذري في قاعدة البيانات. لا تعتبر النظام جاهزًا للأموال الحقيقية قبل اختبار القبول الوارد في التقرير.
