# تفعيل صلاحيات الفروع — خطة نشر آمنة

> هذه الخطوات تخص PR صلاحيات الفروع. لا تنشر كود فرض الصلاحيات قبل تطبيق الـ migration وتعيين حسابات الموظفين، حتى لا تُحجب العمليات عن موظفين يحتاجونها أثناء التشغيل.

## ما الذي يتغير؟

- المالك والإدارة (`owner` و`admin`) يحتفظان بإمكانية إدارة كل الفروع.
- المشرف والكاشير والفني يحتاج كل منهم إلى فرع واحد محدد في عضويته على الخادم.
- اختيار `branchId` في طلب API لا يمنح صلاحية؛ الخادم يقارن الفرع المطلوب بالفرع المسجل لحساب Supabase Auth.
- إذا كانت migration غير مطبقة، أو لم يُعيّن الموظف إلى فرع، يرفض الخادم وصول الموظف إلى بيانات التشغيل بدل إرجاع بيانات جميع الفروع.

## خطوات ما قبل النشر

1. راجع ملف `supabase/migrations/20261019_member_branch_scope.sql` وخذ نسخة احتياطية معتادة من قاعدة البيانات.
2. من Supabase Dashboard افتح SQL Editor، وطبّق نص migration مرة واحدة بعد مراجعتها. التغيير يضيف عمودًا وفهرسًا، ويحدّث قائمة الأدوار المسموحة؛ لا يحذف حركات تشغيل أو بيانات مالية.
3. لا تُعيّن الفروع تلقائيًا للموظفين الحاليين. راجع هوية كل حساب وفرعه المقصود قبل تعيينه.
4. اختبر حساب المالك أولًا، ثم حساب موظف في فرع واحد، ثم تأكد أن الموظف يُرفض عند طلب فرع مختلف.
5. انشر الكود بعد اكتمال تعيينات الموظفين، ثم راجع السجلات والاختبارات من بيئة تشغيل تجريبية.

## API إدارة العضويات

تحتاج هذه الطلبات إلى جلسة Supabase Auth صالحة للمالك، وتُرسل التوكن في ترويسة `Authorization: Bearer <access_token>`.

### عرض حسابات Supabase والعضويات

`GET /api/admin/members`

يعرض معرّف المستخدم والبريد والدور وحالة التفعيل والفرع. الحساب الذي ليس له عضوية تطبيقية يظهر بدور فارغ.

### تعيين موظف إلى فرع

`PUT /api/admin/members/{userId}`

مثال لجسم الطلب:

```json
{
  "role": "cashier",
  "branchId": "liverpool",
  "isActive": true
}
```

القيم المسموحة لـ `role` هي `cashier` و`supervisor` و`technician` و`admin`. الأدوار الثلاثة الأولى تتطلب `branchId` يطابق معرّف فرع في التطبيق. `admin` صلاحية إدارية عامة ويجب أن يكون `branchId` فارغًا. لا يسمح المسار بتغيير عضوية المالك الأساسي.

## اختبارات القبول

- مستخدم بدون توكن: `401`.
- حساب غير عضو أو موقوف: `403`.
- كاشير بلا تعيين فرع: رفض وصول الفرع.
- كاشير تابع لـ `liverpool` يطلب بيانات `chelsea`: `403 BRANCH_MISMATCH`.
- موظف يعرض حالة التشغيل: لا يرى إلا فرعه.
- المالك يستطيع عرض جميع الفروع.
- بيع أو تعديل مخزون أو تسجيل حركة خزنة إلى فرع آخر: يرفض قبل تنفيذ أي تعديل.

## ملاحظة واجهة الإدارة

مسارات إدارة العضويات موجودة في الخادم في هذا التغيير؛ شاشة إدارة العضويات داخل الواجهة ما زالت خطوة لاحقة. إلى أن تُبنى الشاشة، يمكن اختبار المسارات بأداة API موثوقة باستخدام توكن المالك.
